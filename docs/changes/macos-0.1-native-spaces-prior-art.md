# macOS 0.1: native Spaces prior art

Source-inspection prior art only; this study makes no native acceptance claim and changes no product behavior. The selected route keeps native Spaces and native macOS functions with SIP enabled, while retaining the Windows/KDE user-visible model. The [2026-11-27 gate amendment](macos-0.1-gate-proposal.md#gate-amendment-2026-11-27) records the approved limitations separately.

For the separate virtual-workspace alternatives that ship after 0.1, see [macOS virtualised-workspaces mode](macos-virtualised-workspaces-mode.md).

## External review (2026-11-27)

External review dated 2026-11-27 treated these named pins as relevant prior
art: **WhichSpace v1.5.0** (>=27 payload gating and event-targeted switching),
**rift v0.8.6** (augmented >=27 gesture payload), **yabai v7.1.25** (pinned
pre-27 payload and bridged move, including pointer warp that is not adopted)
and **OmniWM v0.8.0** (26+/arm64, read-only native Space inventory with
fullscreen excluded from managed switching).
No native pass or product change follows from the review itself.

- `crates/tiler-macos/src/space_switch_edges.rs:41,95` refuses the pinned
  Dock-swipe payload on macOS >=27 (the rift augmented payload needs an exact
  observed family select). In the current baseline on 27 all switches fall
  back to Mission Control AX under the [managed Spaces decision](../decisions/macos.md#managed-native-spaces-input-and-transfers);
  the [2026-11-27 amendment](macos-0.1-gate-proposal.md#gate-amendment-2026-11-27)
  requires separate proof and pre-dispatch selection, otherwise refusal.
  The MC AX route uses fixed 300 ms stabilization (`crates/tiler-macos/src/mc_probe.rs:70`,
  `crates/tiler-macos/src/mc_lifecycle.rs:612`).
- Measured switch latency is ~1.0–1.1 s on 27 with two extended displays
  ([indicator record](macos-workspace-indicator.md#two-extended-displays-2026-11-27-before-the-click-model-fix));
  the 50–62 ms figures predate 27 ([managed workspaces](macos-managed-workspaces.md#send-latency-work-2026-10-20))
  and are not a 27 result.
- E1 criterion (switch probe): accept only when the target display's current
  Space alone changes, the pointer stays put, no Mission Control flash is
  visible, and fresh readback proves the exact SID. <150 ms is a probe target,
  not evidence by itself.

## Fn/Globe as a tiler modifier

A public CG event tap can observe secondary-Fn **on events the OS produces** ([Apple flag docs](https://developer.apple.com/documentation/coregraphics/cgeventflags/masksecondaryfn)); the physical key's edge is commonly reported as `flagsChanged` at keycode 63, not ordinary key-down/up. Do not match the flag by itself: Hammerspoon also observes it on navigation/arrows and function keys. Prior art tracks the physical Fn edge when present, but it cannot guarantee observing it, infer it from every flagged event, or reserve the chord before OS handling (`swift-macos-tap-detection commit 33c746520b0e8abef3036a2edf852cd59f8650d6:Sources/TapDetection/KeyTapDetector.swift:327-365`, `Hammerspoon 1.1.1:extensions/eventtap/libeventtap_event.m:1549`, `Karabiner-Elements v16.3.0:src/share/monitor/event_tap_monitor.hpp:176-275`). Apple describes the CG flag as primarily found on laptops. External Apple keyboards may provide an Apple vendor Fn usage; generic firmware-only Fn can produce just the translated key, with no host Fn edge. No per-device identity is established at the session-tap layer. USB/Bluetooth, vendor usages and devices should be treated as contrasts, not inferred from their keycap (`Karabiner-Elements v16.3.0:vendor/vendor/include/pqrs/hid/usage.hpp:714-727,745-746`, [Apple F-key setting](https://support.apple.com/en-us/102439)).

| Chord | Native behavior and evidence limit |
| --- | --- |
| Fn/Globe alone | User selects input source, Character Viewer, Dictation or nothing ([Apple Keyboard settings](https://support.apple.com/guide/mac-help/keyboard-settings-kbdm162/mac)); an edge at the tap is not evidence that consuming it stops this action. |
| Fn+F | Native fullscreen menu chord in at least some apps; [Apple Books on Monterey](https://support.apple.com/guide/books/ibk0a716cf4-9a70-485b-9835-72e3c7ed6c29/4.1/mac/12.0) documents it, and [VS Code #141323](https://github.com/microsoft/vscode/issues/141323) reports app differences. Not collision-free; whether an earlier OS handler or app dispatch wins at a tap is not established. |
| Fn+E | Character Viewer ([Apple shortcuts](https://support.apple.com/en-us/102650)); reading an event is not evidence of preventing OS action. |
| Fn+Ctrl+arrows | Native window tiling and related Shift/Option variants ([Apple tiling shortcuts](https://support.apple.com/guide/mac-help/mchl9674d0b0/mac), macOS 15 onward). Karabiner documents that CGEvent-posted Fn does not reproduce this or the standalone Globe action; that does **not** prove physical-event filtering order (`Karabiner-Elements v16.3.0:DEVELOPMENT.md:167-177`). |
| Fn+arrows | May already be Home/End/Page Up/Page Down at the tap. | Fn+F1–F12 | Standard F-key vs media/system event depends on hardware and the F-row mode; the driver translates before the app, and skhd decodes media events separately ([Apple F-key setting](https://support.apple.com/en-us/102439), `Karabiner-Elements v16.3.0:src/apps/CoreService/include/core_service/daemon/device_grabber_details/fn_function_keys_manipulator_manager.hpp:27-45,251-253,283-287`, `skhd v0.3.9:src/skhd.c:162-195`, `src/hotkey.c:280-300`). |

- **Hammerspoon 1.1.1** (13+ build floor) exposes raw flags in public CG session taps; its Carbon hotkey modifiers omit Fn. **skhd v0.3.9** likewise uses a session tap and can drop a matched event downstream, assigning the Fn match bit implicitly to navigation and F-keys; its private CGS Secure Input check is separate. Neither proves priority over system chords or full support on each modern OS; no pin-specific skhd floor established (`Hammerspoon 1.1.1:extensions/eventtap/libeventtap.m:217-229`, `extensions/hotkey/hotkey.lua:159`, `extensions/hotkey/libhotkey.m:258`, `Hammerspoon/Build Configs/Project-Base.xcconfig:15`; `skhd v0.3.9:src/event_tap.c:11`, `src/parse.c:154-186`, `src/hotkey.c:47-66`, `src/skhd.c:44-45,162-195,368,473`).
- **Karabiner-Elements v16.3.0**'s deeper per-device HID capture and virtual HID/DriverKit route is not an ordinary tap: privileged service and extension approval, not a Dock SA or a reason to weaken SIP. The tag's current system requirement is 15+ (older compatible versions listed separately); firmware-only Fn remains invisible. **Fluor 2.5.1** uses an AppKit global monitor plus IOHID system-wide F-key mode writes, not shortcut reservation (floor not established here). **TapDetection** is source-only (11+ per README), uses a CG tap and explicitly handles tap disablement (`Karabiner-Elements v16.3.0:README.md:16-45`, `DEVELOPMENT.md:167-177`, `src/apps/CoreService/include/core_service/daemon/device_grabber_details/entry.hpp:262`; `Fluor 2.5.1:Fluor/Controllers/BehaviorController.swift:230-241`, `Fluor/Misc/FKeyManager.swift:61,76`; `swift-macos-tap-detection commit 33c746520b0e8abef3036a2edf852cd59f8650d6:README.md:124`, `Sources/TapDetection/KeyTapDetector.swift:203-218,254-270`).
- **Permissions and failure modes.** SIP does not need reduction for CG session/AX routes. [Apple CGEventTapCreate](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)) documents assistive access for keys and restrictions on HID-level taps; Input Monitoring/listen access and Accessibility for active taps are distinct from SIP ([Apple Input Monitoring](https://support.apple.com/guide/mac-help/mchl4cedafb6/mac)). A listen-only tap cannot consume. [Secure Event Input](https://developer.apple.com/library/archive/technotes/tn2150/_index.html), app/session consent changes and tap disablement can obscure release; seeing a synthetic event is not evidence of physical delivery or absence of leakage.

**Options and consequences.** Preserve system Globe alone (portable tiler actions use other chords); opt-in passive Fn observation (diagnostic, no binding); experimentally claim an otherwise unreserved Fn chord through the existing active tap (hardware/OS-specific and requires physical no-leak/no-stuck proof); or use a Karabiner-class HID remapper (additional privilege and deployment, outside the product path). Changing global F-row mode changes other apps rather than fixing a local conflict.

**Recommendation — no Fn/Globe tiler modifier in either 0.1 preset.** Keep configurable browser/terminal launchers unbound in both presets, suggest Ctrl+Alt+B/T without promising universal availability, and preserve native Globe/F-row preferences. If later investigating a custom Fn chord, start with passive discrimination of keycode-63 edges/translated events, then separately prove one claim per physical press and no native side effect on supported keyboard/OS variants. Exclude the known native chords above.

## Multi-display indicator

Per-display **presentation** is feasible in prior art; a reliable SIP-on **selector** is a separate question. Native `NSStatusItem` is managed by the system status bar and has no public per-display content API ([AppKit](https://developer.apple.com/documentation/appkit/nsstatusbar)). A native managed-display row is keyed by private SLS/CGS display UUID (or `Main` for a shared Space set), with its own current SID and ordered Spaces. This is not the active menu-bar display, pointer display, focused-window display, or an ordinal. Public CG/AppKit supplies screen UUID/geometry and configuration changes, not a native Space topology or select API. Private reads and drawing one's own windows do not entail Dock injection.

**Options and consequences.** Safe-hide prevents misrouting but fails coverage if kept as the whole answer. A single mirrored item with labelled output groups can cover the display data without overlay side effects, but is not a pager per physical output. Dedicated nonactivating windows per output are closest to Windows/KDE; they need hotplug/reanchor, fullscreen/game suppression, and routable exact-target clicks regardless of where menu bar, pointer or focus happen to be. Copying yabai's pointer warp and corrective click makes the gesture visible and can alter focus; global Desktop shortcuts cannot stand in for exact destinations. A direct SA selector changes the security posture and is out of scope. Mission Control AX is visible and hierarchy-sensitive, but is the strongest SIP-on route to test first because it explicitly addresses the target display without pointer warp.

**Recommendation at survey time — keep the 0.1 blocker and pursue a per-output pager.** Separate the surface from the actuator: project the existing core rows (including only a core-designated unbound spare) by exact output/workspace, then reconstruct and compare the fresh UUID↔managed row↔SID binding at action time. Prefer the existing Mission Control route extended to validate the correct AX display group and current order before one press, then verify exact SID arrival **on the target row** and no unrelated row changed; do not replay or silently fall back on a failed read. Accept visible Mission Control only if it meets consistency and safety, otherwise report the failing discriminator, not success. In unified mode show one shared native selection, never independent current Spaces; state the mode explicitly. Preserve safe-hide/disarmed clicks for unknown topology, fullscreen/game suppression and stale tickets. Later source-to-native discriminators: two displays with focus/menu bar/pointer disagreeing; inactive-output empty target; reorder/unplug during pending click; explicit unified-mode run; fullscreen on either output; suppression and return. No clean secondary-output acceptance follows from source. **Superseded 2026-11-27:** the user selected one shared `NSStatusItem` with per-display groups and rejected an app-owned nonactivating strip ([selected design](macos-per-output-indicator.md#selected-design-and-implementation-scope)); the safety assertions above still apply, but a per-output pager is not the selected 0.1 surface.

OmniTiler currently fences both managed-row and core pager counts (`crates/tiler-macos/src/workspace_indicator.rs:319-359`) and actuation (`crates/tiler-macos/src/workspace_select.rs:746-758`); existing pager rows already carry output/workspace/native identity (`crates/tiler-macos/src/pager.rs:47-85`). The [MX6 fixture gap](macos-core-trailing-pager.md#offline-empty-destination-diagnosis) is independent: native current changed on the empty destination while core kept the prior current because hidden inventory was incomplete. Capture correlated facts and distinguish native landing, painted current, accepted core publication, and click authority; rendering read-only native current must not grant authority or fabricate occupancy.

[Check 6](macos-0.1-gate-proposal.md#original-checks-1-53) keeps physical hold/release, repeat/maximize and no-leak assertions; only native foreign-window sticky is excluded by the [2026-11-27 amendment](macos-0.1-gate-proposal.md#gate-amendment-2026-11-27). [Check 32](macos-0.1-gate-proposal.md#original-checks-1-53) is a documented native SIP-on limitation, not a pass. Partial membership counts, app-level placement, and serial movement are not equivalent.

### Bounded signed-fixture probe (2026-11-27)

- SIP was enabled. The signed diagnostic's normal SkyLight connection
  resolved `SLSProcessAssignToAllSpaces`. Its known ABI takes a connection
  and PID, not a window ID; the process-wide entry point was not invoked.
  The per-window tag readers/writers and SLS membership reader also resolved.
- **Stopped before the tag write.** The sidecar could not bind the active
  product through its LaunchServices process-argument check. By the time it
  tried to join the fixture window, the controller had already finished and
  closed it; there was no authenticated target and no tag mutation. The
  controller restored the original topology and left no owned residue.
- No foreign tag efficacy or post-switch membership was measured. At probe
  time the unsupported behavior and checks 6 and 32 were unchanged and the
  conditional gate amendment had not been triggered; the separate
  2026-11-27 [gate amendment](macos-0.1-gate-proposal.md#gate-amendment-2026-11-27)
  now documents the limitation without treating this stopped probe as a pass.
- The launcher did not forward the settle environment through `open`,
  and the sidecar waited on process arguments unavailable through
  LaunchServices. The pager returned and tore down automatically with
  no probe handshake. The restore guard relied on an AX title join
  that can disappear off-Space, and skipped restore if the immediate
  post-write tag read was unreadable. Fixing the trigger alone would
  not make that restore safe.
- A bounded retry needs synchronous controller ownership of the tag
  set, the exact away destination and return, fresh SLS membership
  reads before and after the switch, and an unconditional one-bit
  restore while owner identity is proven.
- The synchronous controller was not pursued to a live run. The existing
  harness has no masked per-window tag bindings or restore-first path
  that keeps the exact signed fixture owner authenticated after its AX
  title is no longer readable off-Space. Adding those pieces and a
  pinned empty away Space was more than a small diagnostic change.
  No tag was written and no new measurement was taken. At probe time checks
  6 and 32 retained their then-existing requirements; the later 2026-11-27
  amendment is recorded in the [gate proposal](macos-0.1-gate-proposal.md#gate-amendment-2026-11-27).

## Project-owned native fullscreen

The leading route is to **set** `AXFullScreen` to an explicit boolean using public [`AXUIElementSetAttributeValue`](https://developer.apple.com/documentation/applicationservices/1460434-axuielementsetattributevalue); the state attribute's name is undocumented and is not the documented [`kAXFullScreenButtonAttribute`](https://developer.apple.com/documentation/applicationservices/kaxfullscreenbuttonattribute). Other apps can expose either attribute, neither, or a disabled button. Using public AX transport is SIP-on with Accessibility; private `_AXUIElementGetWindow` is sometimes used to join to CG identity, not to enter fullscreen. Request acceptance is not a settled native Space or an exact windowed restore.

No surveyed implementation uses **press fullscreen button** for this command, and none demonstrates exact pre-fullscreen windowed restoration across foreign apps. An enabled button and exposed `AXPress` could give a SIP-on action for specific windows, but it is a *toggle*; no guarantee of direction, same-lifetime settlement, or identical behavior to the setter. Existing OmniTiler read-only inspection joins the exact button accessor; the fixture setter writes and checks the same lifetime, reporting readback mismatch without geometry writes. Neither is product authorization or proof of native Space settle and exact restore (`crates/tiler-macos/src/scope_inspect.rs:246-297`, `crates/tiler-macos/src/ax.rs:1274-1284,1307-1355,1378-1412`). Unknown/unsupported, disabled, transient AX results, and ambiguous Space transitions are separate conditions; no specific refusal guarantee follows from an admission heuristic.

**Options and consequences.** Prefer a settable state attribute with identity and later observation, scoped to positively eligible windows. A separately qualified `AXPress` path might cover more apps but adds a direction race; never issue it as a blind fallback after an ambiguous setter. Windowed fill duplicates composed maximize, does not preserve a native fullscreen journey and is not R14 parity. Host-only observation remains fail-closed until a conforming native actuator is proven, not a scope waiver.

**Recommendation — pursue the state setter; keep capability off until proven.** Core retains command/refusal authority, membership/share, and the independent maximize overlay ([R14](../decisions/contract.md#window-state-commands-r14)). Capture an inert exact windowed preimage (lifetime/native home/output, point frame, base and overlay) before ONE authorized attempt. Read window flag and current native Space type/membership after the request until the exact lifetime and expected arrival settle within a bounded deadline; while ambiguous, no geometric or focus repair and no opposite toggle/replay. On owned exit, wait for windowed Space settlement, then verify exact return when the preimage/base is still authorized; otherwise use only core's current retained base/overlay authority, never stale geometry on a changed display or lifetime. If drift or loss prevents proof, keep the transition strictly fenced and expose recovery status, do not adopt app-owned exit or claim restore. For later verification: signed-fixture tile/float/maximized entry and exit; exact AX/CG frame/current-base proof; unsupported and unresponsive apps; rapid repeat, external exit, same app new window, display unplug, termination/restart with pending/unknown state. No native game/carry/suppression gate is relaxed.

**Synthesis.** Borrow topology and identity from native-first tools, not privilege assumptions or their default settings; borrow Defi's explicit spare invariant, not its parking. A consistent shared model does not require the same platform actuator: core owns workspace order/current semantics, per-window lifetime and membership, retained layouts and explicit trailing role; the macOS adapter maps real native rows and provides bounded, positively observed operations. A fullscreen Space is a native cover, not another ordinary workspace. Shared topology is not independent per output. A virtual workspace catalogue, app hiding, and split invisibility through frame moves are different products, not automatic fallbacks for missing native authority.
