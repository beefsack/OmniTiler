Review only: no product code, tests, or fixtures changed. Scope is the active v4 wire, the typed core boundary, broker/evaluators, KDE producer and consumers, settings exporter and fixture-facing contract. Deferred macOS/Windows internals are excluded. Evidence is static source/reference inspection; no builds, tests or live runs. Sizes are estimates of source/test changes, not measurements; fixture churn is separate. A: no behavior change. ### PW-BR-01 — Decode the broker capture object once (F8 remainder)

`crates/omnitiler/src/world_broker.rs:876-953,1312-1331,1992-2080` and `crates/tiler-protocol/src/world_protocol.rs:3961-3989`: the strict outer parser already recursively builds a duplicate-checked tree. Preserve both independent byte gates: count the exact compact stamped encoding with byte-equivalent semantics before removing the intermediate string, rather than estimating from the outer capture length. Keep raw attempt-clock checks in their current refusal order until PW-BR-04 is decided; borrowing the map needs no second copy. Consumer effect: no change in wire, replay bytes, rejection precedence or evidence; less whole-capture processing. Risk medium, particularly numeric/string encoding equivalence and error precedence. Estimate 35–75 lines changed; no fixture re-recording. Existing guards: `capture_envelope_rejects_duplicate_outer_and_nested_keys` and `b6_strict_ingress_rejects_duplicates_and_preserves_precedence` (`world_broker.rs:3013,5237`). Depends on preserving strict source-replay and byte gates, not a wire decision.

Done: the broker decodes the stamped report map directly; both byte gates and replay/refusal ordering are retained, with an exact compact-encoding test.

## B — decisions

### PW-ROSTER-01 — Match setter readbacks to the exact plan step before reducing them

`crates/tiler-protocol/src/world_roster_wire.rs:482-548` accepts a changed `home`, changed `current`, or ordered single deletion under any `applied` step ID. It then erases the readbacks from the value core receives. `crates/tiler-core/src/world_roster/proof.rs:14-20,75-110,124-186` correlates the ID and dependencies and requires a newer report whose entire observed roster, occupancy and view match the desired result, but cannot check whether the *setter* evidence matched its step kind, preimage and target. A member step with a `current` change (or a different home delta) reaches the same `Applied` status as the correct change; independently matching later observations would suffice to accept it [INFERENCE from those predicates, not reproduced]. The contract requires the actual prefix/readbacks and plan correlation (`docs/porting/world-contract.md:824-865`). **Options:** explicitly reduce the wire to an adapter disposition and append identity, relying only on fresh final observation; or carry typed `before`/`after` through to the plan owner and verify each row against the correct step, including exact single append/removal identity/order, before latching its receipt. **Recommendation:** latter, keeping the existing `{op,gen,rev,steps:[{step,status,before,after}]}` shape and independent final observation; do not move plan/actuation policy into the decoder. The existing `roster_feedback_preserves_exact_readbacks_and_replay_identity` (`crates/tiler-protocol/tests/report_optionals.rs:132-215`) explicitly demonstrates distinct raw evidence reducing to identical proof; add wrong-kind, wrong-target and correct readback with delayed observation to `crates/tiler-core/tests/support/shared_roster_slots.rs` and the real broker route. Consumer effect: inconsistent proof no longer authorizes epoch advance; valid KDE wire bytes and real active fixtures should not need re-recording [INFERENCE]; typed hosts implementing this optional capability would use the same proof. Risk high for workspace settlement and avoiding indefinitely blocked valid plans; estimate 90–200 source/test lines. Independent of the optional-field cleanup, but do before someone treats `RosterStepProof` alone as portable authority.

Related refusal decision: `crates/tiler-core/src/world_roster/proof.rs:67-70,106-110,124-133` records `Refused` but success requires `Applied`; KDE emits refused readbacks (`kwin/src/world-roster.ts:338,401-407`). An unresolved refused epoch can keep writes held (`world_roster.rs:183-200`) [INFERENCE]. Treat refusal as terminal for that epoch, then replan only from a fresh observation proving the actual partial state; never assume a failed setter left the original roster intact. Add active refusal and partial-application regressions alongside the readback check.

Done: core verifies typed setter readbacks against the exact plan step, retains independent observation proof, and retires refused operations without assuming rollback; core and broker regressions cover mismatches, delayed observation, refusal and partial application.
