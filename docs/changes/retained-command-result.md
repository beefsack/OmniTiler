## Proposed design

- **Mechanical separation (both Q1 options)**: `DragPreview` is active gesture overlay state with real drawing consumers (`CarriedPreview`, `map_gesture_preview`), not a command outcome. Move it to a dedicated nullable `dragPreview` slot on `WorldReplyV4` and remove `DragPreview` from `CommandResult` so preview state and command outcomes never overwrite each other.
- **Retained `dragPreview` lifecycle**:
  - Slot carries `{ id, rect, hover, domain, source, target, revision }` (`id: u64` from `retained.id`) per `(adapter, gen)`. `id` binds to the active gesture so an old preview cannot repaint a replacement gesture; redelivery is inert.
  - Omitted/commandless ingress while a gesture is active returns `GestureOutcome::Held` (`C/world_gesture.rs:269-284`): **preserve** the latest `dragPreview` across omitted ingress and skipped replies (unlike today's per-run clear at `C/world_run_v4.rs:438`), unless current core safety/scope gates (`gesture_continue_fences`, `gesture_game_paused` at `C/world_gesture.rs:520-525`), subject/neighbor departure, or invalidated domain/neighbor invalidate it even on omitted ingress (extension from active-sample fences to omitted-publication validity is proposed; no new timer or ack).
  - All genuine current-session active `Held` no-preview outcomes clear `dragPreview` to `null` to preserve existing hide behavior: bind-only `Started` (`C/world_gesture.rs:310-314`), `gesture_continue_fences`/`gesture_game_paused`/`is_owned_composed_float`/non-`Move` (`:520-534`), missing cursor (`:535-538`), zero movement (`:540-546`), `gesture_pair_preview`/`gesture_local_event` `None` (`:580,595`), and engine refusals self/centre/outside/unchanged (`:611-613`). Mismatched ignored newcomers (`:285-303`) cannot relabel an old id or authorize a newcomer preview. Explicit `Released`, `Cancelled`, proven owner departure (`staged.closes` at `:275-282`), or fresh handshake/new generation also clears to `null`.
  - Broker `CarriedPreview` (`B/world_broker.rs:934-944,2173-2191`) keeps the output-level suspension gate (`domain.output == presentation.suspended_output`). Because `active_assoc()` at `B/kde_gesture.rs:250-255` is currently `#[cfg(test)]`, production adoption must expose a read-only exact-id accessor over that existing `active_assoc` pin (reconciled before projection at `B/world_broker.rs:859-877`, no second map needed) and match `dragPreview.id` against it instead of current-capture `gesture_assoc` alone. Missing/mismatched association stays unproven (`producer: null`), never guessed; same-gen reconnect preserves, fresh handshake clears with the core slot, and preview freshness/current-generation fences remain.
- **Retained non-preview `result` (under Q1 A)**:
  - One global latest-executed-command slot per `(adapter, gen)` (not per-owner history; private per-command collection stays broker-owned per `docs/decisions/contract.md:70`), shaped `{ cmdSeq: u64, outcome: CommandResult | null } | null` (`cmdSeq` encoded as bounded quoted decimal). A successfully executed command producing `None` replaces its predecessor with its own `cmdSeq` and `outcome: null`, preserving `null` semantics with no invented `Applied`/`NoOp` verdict.
  - Distinguish command decision terminal from later native settlement: keep the last completed outcome while a successor is pending/unexecuted; replace only on command execution/decision (including `Rejected`); `Duplicate` and `CommandConsumed` never regress it. Identity match never reruns a command or grants native authority.
  - Owner cleanup (carrying over [settlement Q1/Q2](retained-settlements.md#user-decisions-2026-11-14)): `Float`, `Maximize`, and `Directional` (`Some(target)`) remove on proven `target`/`window` departure; `Migration` removes on either `source` or `target` output departure; `Rejected` and `Directional` (`target: None`) are generation-scoped. On owner-keyed removal, emit a trace-level diagnostic carrying the final dropped outcome. Never parse ids. Initial/removed is `null`; hold/incomplete retains; fresh handshake resets; same-generation reconnect retains.
  - Bounds: singleton slot plus existing payload/vector caps and 4 MiB reply bound; no arbitrary expiry or history. Broker still strips `result` on actuator replies.

## User decisions (2026-11-15)

- Q1: **B**. Remove `result` from `WorldReplyV4`; the issuing `Vec<BatchSettlement>` and broker requester-only `TakeCommandResult` are the sole command-outcome path. Why: no production v4 adapter reads non-preview `result`, one mechanism per job, and Tier 1 delivers command outcomes only to the requesting caller. Accepted cost: protocol-only inline callers inspecting only `WorldReplyV4` lose non-preview outcomes. Q1 A material below is historical.
- The mechanical `dragPreview` separation and its retained lifecycle proceed as proposed (presented with Q1, no objection).

## Q1 record (decided)

### Q1: Retain latest-wins `result` on `WorldReplyV4` or remove it?

- Evidence gap: no v4 adapter reads `WorldReplyV4.result` for non-preview outcomes today (broker strips it to `null` for KDE; macOS reads only `DragPreview`; Windows is not on v4). `BatchSettlement` is returned only on the issuing `handle_report` call (later commandless calls return an empty `Vec`); broker `TakeCommandResult` retains copied outcomes across later commandless reports within `MAX_SETTLED_RESULTS = 1024`. Removing `result` does not make ephemeral `BatchSettlement`s durable for direct in-process callers: they must consume the issuing `Vec<BatchSettlement>`. Inline `report.command` with empty `queued` emits a `BatchSettlement` on `handle_report` (`C/world_run_v4.rs:501-507`), but protocol-only inline callers inspecting only `WorldReplyV4` (e.g. `C/world_admit_v4.rs:800-805`) lose non-preview outcomes under B.
- Options: (A) Retain latest-wins `result: { cmdSeq, outcome } | null` on `WorldReplyV4` (broker still strips for actuator privacy). (B) Remove `result` from `WorldReplyV4`, keeping `Vec<BatchSettlement>` + broker `TakeCommandResult` as the sole command-outcome path.
- Consequences: B removes a wire lane unused by current production v4 adapters, removes redundant batch-last projection while existing private per-command results remain, saves reply-byte overhead, and obeys Simplicity (one mechanism per job) while preserving `docs/decisions/contract.md:70`. A preserves wire-level latest-outcome visibility for protocol-only inline callers at the cost of a second outcome lane. **Rec: B**.
- Tier 1 evidence: `i3` (`4.25.1:src/ipc.c:207-230`), `sway` (`1.12:sway/ipc-server.c:638-666`, `sway/commands.c:509-528`), and `Hyprland` (`v0.57.2:src/SharedDefs.hpp:40-45`, `src/ipc/s1/Commands.cpp:1332-1350`) deliver command outcomes only to the requesting IPC caller, not in a global world-state broadcast; `cosmic-comp` (`epoch-1.11.0:src/input/actions.rs:43-50`) handles actions in-process with no external command-result reply lane found in `actions.rs`.

| Variant | Minimal action sequence | Candidate outcomes |
| --- | --- | --- |
| Skipped reply after command | Queue `toggle-float` (`cmdSeq=1`), skip issuing `WorldReplyV4`, then send commandless report | A: `WorldReplyV4.result` retains `{cmdSeq:"1", outcome:Float}`; broker `TakeCommandResult` returns `Float`; commandless `handle_report` `Vec<BatchSettlement>` is empty. B: `WorldReplyV4` has no `result` field; `TakeCommandResult` returns `Float` across later commandless reports; commandless `handle_report` `Vec<BatchSettlement>` is empty |

## Test and native-check plan (future only)

- `dragPreview`: retain across omitted/commandless ingress and skipped replies, then hide to `null` after invalidation (scope hold, game pause, or domain/neighbor departure) without new gesture ingress; clear to `null` on active `Held` refusals/bind-only/zero-move/composed-float/non-`Move`, `Released`/`Cancelled`, `staged.closes`, and new generation; `id` prevents old preview repainting a replacement gesture and ignored newcomers cannot relabel/authorize; broker `CarriedPreview` preserves `producerInstance`/`producerSerial` via the exposed exact-id `active_assoc` accessor across skipped originating runs and omitted ingress (missing/mismatched stays unproven).
- Q1 A: `{ cmdSeq, outcome: null }` replaces predecessor on `None`-producing command; `Duplicate`/`CommandConsumed` never regress; window/output departure cleanup and trace diagnostic; exact codec/sizing bounds.
- Q1 B: issuing `handle_report` returns `BatchSettlement` (including inline `report.command`), later commandless `handle_report` returns empty `Vec`, broker `TakeCommandResult` retains across later commandless reports with `MAX_SETTLED_RESULTS` isolation/eviction.
