# Implementation minimisation review

Pre-0.1 static review against `c9d7e5c9`. Goal: reduce implementation and test surface before the macOS and Windows rebuilds, without changing product code, tests or fixtures in this review. Scope: portable core, Linux service and evaluators, KDE settings exporter, KWin script and effect, repository tooling, and test support. Deferred ports are considered only as consumers. Wire/contract changes are listed separately, not evaluated here.

A = zero-behaviour deletion for supported consumers; B = behaviour/design decision; C = deliberately keep. Sizes are estimates, not applied diffs. The listed gates are proposed for implementation, not results of this review. A-unit gates are independent; none requires another unit to land first unless stated. Review evidence is static; no builds, suites or native actions were run.

Rust symbol evidence uses `rust-analyzer` `textDocument/references`, checked against whole-repository `git grep` (which also detects docs and off-target source missed by the index). Other reachability evidence uses source, manifest and documented invocation searches.

## Priorities

**15 A findings in 12 independent units; 2 B decisions; 9 C keeps.** Start with the retired raw KDE normalizer/corpus (~3,337 lines) and floor-ratio scaffold (~1,233 lines). For porting clarity, narrow the 17 internal core modules, gate seven test helpers, and remove the callerless Rust API before onboarding new native adapters. The largest verified test-only deduplication is the core admission-test gate (~475–490 net lines). The two decisions are evaluator consolidation and KWin source-pinning tests; neither justifies deleting unique behavioral coverage. Handed-off items are not in these counts.
