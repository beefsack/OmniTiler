# macOS workspace-model review

## Goal and scope

- Produce a pinned-source research comparison of native Spaces and configurable
  virtual workspaces, including trailing-spare presentation and core reuse.
- Deliverable: [workspace-model review](../../research/macos-port/workspace-model-review.md).
- No product changes, native experiments, or changes to existing decisions.

## Acceptance and approach

- Inspect the named macOS reference tilers at the existing documented pins.
- Distinguish source facts, upstream claims, recommendations, and unknowns.
- Compare shell/fullscreen/recovery risks and existing core hidden-workspace
  behavior; estimate effort and identify mode-specific native work.
- Recommend, rather than select, product changes against Vision and principles.
- Verify citations, scope, and whitespace; publish only the research and this
  completed record.

## Units

1. Extract virtual-workspace and pager evidence from AeroSpace, rift,
   komorebi-for-mac, and FlashSpace.
2. Extract native/strip workspace and pager evidence from yabai, Amethyst,
   glide, paneru, Hammerspoon, and PaperWM.spoon.
3. Inspect existing core/Windows hide-reveal and macOS adapter contracts;
   synthesize the research record and review its evidence.

## Outcome and evidence

- Compared eleven macOS references at documented pins, including Defi's explicit
  trailing-empty design and its empty-view keyboard-target caveat.
- Existing core logical workspaces support adapter-owned hide/reveal. Parking
  still needs geometry recovery, truthful receipts and fullscreen/shell proof.
- Recommendation: native default, future opt-in feasibility work; M prototype,
  L production; S explicit core trailing designation useful in either mode.
- No existing product decision changed. Optional mode retires no native backlog;
  native-only mechanisms are unnecessary within virtual ordinary-workspace mode.
- Citation/path and scope review completed; no new runtime acceptance claimed.
