# macOS focus and admission adoption

The macOS v4 adapter was audited against the [world contract](../../porting/world-contract.md), [focus decisions](../../decisions/focus.md), and [admission decision](../../decisions/layout-and-admission.md#inactive-destination-admission). The three offline routes were already present. Native safety fences and Windows behavior are unchanged.

## Offline evidence

- **Unavailable pending-focus command subjects — already adopted.** `runtime_thread.rs:1949–1976` does not substitute observed foreground or locally refuse an implicit subject; `world_command_map.rs:341–405` maps the keyboard operations, and `runtime_thread.rs:2793–2839,2949–2968` sends the implicit numbered send and pins the core-selected lifetime and source before the native claim. `operation_without_local_focus_dispatches_and_core_resolves` and `send_hidden_domain_subject_refuses_at_apply_time` exercise both seams. Core alone resolves the cursor and newer accepted observation (`world_close_focus.rs:151–220`); `unavailable_pending_same_batch_refuses_then_newer_report_acts_on_observed_and_recovers`, `unavailable_pending_newer_unknown_or_unbound_foreground_refuses`, and `failed_record_command_focus_clears_prior_cursor` pin the decision. Native recovery and command targeting remain unverified.

  The adapter reports the observed foreground and omits unreadable Space members (`world_runtime.rs:1344–1353,1409–1429`; `world_builder.rs:521–531`; `unreadable_scope_holds_without_write_authority`). This is enough for core to detect an unavailable target even though macOS does not emit `held_windows` rows. Sequencing advances the request while a command can reuse the observation watermark (`world_sequencer.rs:304–330`; `unavailable_pending_newer_accepted_report_with_equal_observation_seq_acts_on_observed`). Native verification must observe the different bound foreground before claiming fallback recovery.

- **Perpendicular focus recency — already adopted.** `world_command_map.rs:341–355` forwards directional focus and move as `CurrentFocus`, without selecting a neighbor. `runtime_thread.rs:1623–1664` attributes cursor hits and sends observations, not focus decisions; `hover_core_producer_codec_latest_mock_actuator` (`world_dispatch.rs:13249`) exercises the retained hover request. Core owns the tie-break (`directional.rs:1269–1310`); `perpendicular_descent_both_histories_abc_vs_bac` and `perpendicular_descent_accepted_hover_not_overwritten_by_lagging_foreground` distinguish accepted recency from fixed order and stale foreground history. `directional_edge_is_accepted_envelope_with_typed_rejection`, `native_focus_walk_retains_at_edge_per_tier1` (scripted backend), and core's `local_focus_history_descent_edge_and_nonfixed_point_tails` cover the command and local-policy layers. Native proof remains for perpendicular choice, focus-edge stay, in-group swap, move-edge no-op and unchanged cross-output behavior.

- **Batch 3 admission — already adopted for reported facts.** `world_runtime.rs:1263–1281` gathers retained members by domain and `world_builder.rs:511–545` emits members of readable current and inactive Spaces; `retained_occupancy_groups_current_and_hidden_members` exercises the grouping. Core spends the inactive birth rather than requesting focus (`world_model.rs:1731–1732,1810–1822`; `inactive_workspace_birth_anchors_remembered_without_focus_or_switch_and_never_replays`). `native_tile_backend.rs:651–658,767–779` supplies raw observations without a classification verdict; `runtime_core.rs:378–383` and `world_builder.rs:635–638` use `normalize_window_type` (`runtime_types.rs:546–562`). `normalize_window_type_uses_factual_neutral_vocabulary` verifies `AXFloatingWindow → Utility`; core's `utility_and_splash_float_as_ordinary_members_including_nullable_unrelated_facts` and `utility_and_splash_retain_safety_owned_and_tool_window_gates` verify the float outcome and its fences. The older classifier serves border diagnostics and inspection, not v4 admission, so removing it would not eliminate a production admission veto.

  [Prior native measurement](../macos-batch3-utility-mapping.md) identifies standard utility panels. `AXSystemFloatingWindow` stays unknown under the [approved withholding decision](../macos-v4-open-decisions-review.md#decision-3-axsystemfloatingwindow-mapping); changing it to `Other` would also hold it, while treating it as `Utility` requires an actual sample and a decision. No macOS splash or PiP kind is inferred. AX may not expose a new off-Space window until return; CG/SLS rehoming is restricted to retained lifetimes (`runtime_core.rs:1122–1142`) and does not prove fresh off-Space discovery. Native admission/no-replay, utility float behavior, splash/PiP facts where observable, and fullscreen return safety remain unverified by this audit.

No runtime change or new regression was needed. Windows scope is unchanged.
