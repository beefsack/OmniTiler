# KDE v4 acceptance re-baseline

## Goal and scope

Map the approved 57-check release inventory and KDE pending/open-work legs to
v4 behavior and evidence after offline phase 2. Publish one user-owned KDE
acceptance checklist without changing approved release acceptance.

Non-goals: product changes, native testing, Windows acceptance changes, or
retirement of must-pass/0.1 requirements without a user decision.

## Acceptance and approach

- Inventory each numbered check and remaining KDE pending/open-work leg.
- Separate available scenarios/tests from recorded execution and physical proof.
- Consolidate executable physical legs, identifying 0.1 and macOS gates.
- Retire only superseded implementation routes with evidence; retain decisions.
- Preserve historical records and non-KDE scope; consolidate approved backlog scope.

## Units and verification

1. Inventory historical requirements and current v4 evidence.
2. Integrate a single checklist and reconcile every source item.
3. Verify whitespace and relative links; review acceptance/count consistency.
