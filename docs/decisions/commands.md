### Workspace tiling intent
- Decision: `ToggleWorkspaceTiling { output, workspace }` flips retained core mode at execution; `SetWorkspaceTiling` is for genuine explicit choices. KDE shortcut/tray and Windows toggle callers use neutral intent; repeated queued toggles compose. Wire is `toggle-workspace-tiling` with `out/ws`, never `tiled`.
- Why: not recorded.

### Directional focus without a focused window
- Decision: when directional focus has no focused window, encode the subject as an explicit empty `win` for both in-process and JSON callers. Missing, null or invalid ids, and empty ids on other commands, retain strict validation. The explicit current-focus object has the separate execution-time meaning in [KDE rapid input](#kde-rapid-input), never the empty marker's no-focus meaning.
- KDE (User 2026-11-17): KWin desktop-type foreground counts as genuine native absence for that empty directional-focus subject only. Other foreign foregrounds (panels, other shell surfaces, apps, games or fullscreen windows) still refuse. Native foreground remains truthfully reported; no native clear-focus is issued.
- Why: not recorded.
- Assumes / revisit if: no-focus behavior is described in [workspace lifecycle](workspaces.md#workspace-lifecycle-focus-and-history).
- Status: active, 2026-10-27
- Evidence: [directional focus without a window](../changes/archive/directional-focus-without-window.md).

### Ordered core commands and latest-world application
- Decision: core processes every queued command in press order against the state left by the preceding command, without depending on native application. This rule is platform-independent and also applies with no adapter present. When an adapter is present, it receives world updates and applies only the latest world it holds: superseded unissued targets drop, while an already-issued native write completes before advancing. Skipping native intermediate worlds never skips core commands.
- One mandatory prepared ingress accepts a strictly increasing list of at most 128 commands, including the inline wire pair normalized as a proof-bearing first entry. Every entry passes the same v4 vocabulary, subject and renderer-proof rules. Invalid or disordered fresh batches receive `snapshot-invalid` with `command-invalid` or `command-order-invalid`, respectively, before incorporation, with no dispositions and no sorting. A consumed entry does not prevent later fresh entries. Exact report replay is a cached publication (`ReportIncorporation::Replay`) and does not admit a new queue; accepted outcomes are independent of native apply and skipping intermediate worlds. User decision (2026-11-20): pre-inspection whole-capture refusals (owner/correlation/adapter/generation/capability/arrival/size/report-structure and stale/reused request fences) short-circuit as `ReportIncorporation::NotAdmitted` with empty dispositions without enumerating per-sequence receipts, while valid post-inspection refusals (observation stale, preflight, caps, or later staged gates) retain `NotRun` for the already-validated identities.
- Why: every rapid keypress must be fully processed; native rendering must not become a per-action execution barrier.
- Assumes / revisit if: semantic eligibility/refusal rules still apply; ordered processing is not a promise every command succeeds.
- Status: active, User 2026-11-16.
- Evidence: [adapter-free batch regressions and KDE correction](../changes/kde-rapid-input-latest-world.md#float-fifo-correction-2026-11-16).

### KDE rapid input
- Dispatch and core ingress: user commands preempt an armed native-event debounce; only native-event bursts wait 120 ms. The broker files commands in one global FIFO across client namespaces, assigns global execution order and keeps outcomes requester-only. ACK confirms filing, not execution. User decision (2026-11-20): broker pre-drain rejections leave commands parked; when a drained capture returns `NotAdmitted` or another recoverable rejection/duplicate, broker queue ownership restores the drained batch at the FIFO head in order without synthesizing receipts, while an inspected internal-drain invariant fault (`command-invalid` or `command-order-invalid`, never `NotAdmitted`) is logged and rotates generation without publishing or inventing results; recoverable late prepare failures repark the drain at the FIFO head. [Ordered ingress](#ordered-core-commands-and-latest-world-application) is shared with the typed route.
- Decision: KDE implements [ordered core commands and latest-world application](#ordered-core-commands-and-latest-world-application) through FIFO filing without busy refusal. For an implicit registered shortcut (including Meta+G), KWin seals the observations at callback entry. Presses share a cut only across unchanged subject-relevant native state with continuous evidence; foreground and selector transitions split even when proved own, and gaps split. One local segment owns Queue through the ready Describe ACK; the broker still drains its whole FIFO and external senders have no keypress-order promise. `win:{"currentFocus":true}` resolves before each action against state left by the preceding action; it does not mint a compensating focus setter. Explicit by-id and empty directional-focus subjects keep their meanings. A coherent press may be refused only on real saturation; an unprovable cut may be refused. An irrecoverable filed cut triggers generation rediscovery, also discarding parked external entries. Exact capture replay and definitive NotRun retry keep the cut, not a later snapshot. Internal hover/drag and unfloat continuations retain their routes. See [the native-cut change](../changes/kde-shortcut-native-cuts.md).
- Why: i3, sway, Hyprland and COSMIC dispatch every matched press sequentially ([stable-tag float discriminator](../spec/reference-outcomes.md#kde-queued-execution-time-subject)); one queue removes the directional-only branch and busy refusal.
- Assumes / revisit if: incoming close and attempt evidence survives skipped native publications. Close currently reports native lifecycle state, not an outgoing close command; any future non-idempotent command needs retained work that supersession cannot drop. Physical-key and perceived-latency acceptance remain pending.
- One retained focus request is state: every latest publication carries the same pending id until satisfaction, supersession, ineligibility or refusal. Unused one-shot raise/stack shapes are removed, not another delivery mechanism. An adapter may skip the issuing publication and act once from a later snapshot, never needing intermediate replies. Each bound id is spent before one native attempt or safety no-call; lost feedback and unchanged reemission never authorize another call. Incoming observations can retire it before any native apply. Non-focus commands never cancel pending focus in any batch, including refused commands without a focus decision; only a newer focus decision, an observed user focus change, a view change or target loss making the target ineligible supersedes. Core/protocol implement this direction; coordinated adapter adoption and native acceptance remain incomplete ([design](../changes/retained-focus-requests.md)).
- Status: active; capture-boundary implicit-subject focus mismatch is corrected and all seven scoped gates pass. A post-correction injected burst, mapped once from observed fixture order, settles all 60 commands READY with zero refusals and final native/core agreement. Earlier 51 refusal causes remain individually unavailable; correct semantic refusals are allowed and queued refusals now retain per-command internal reasons. Four presentation-hide diagnostics remain unclassified. Independent latest-only native history, physical-key and perceived-latency acceptance remain open, 2026-11-08 (user decision; explicit execution-time subjects and single-capture batch execution supersede the 2026-10-19 directional-only tentative entry) User 2026-11-09 dogfood: navigation and window moves felt near-instant, the most responsive to date (informal perceived-latency evidence; formal acceptance still open).
