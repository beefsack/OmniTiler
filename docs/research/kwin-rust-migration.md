# KWin-to-Rust migration

- Recommendation: extend the out-of-process Rust planner first; keep native observation, actuation and immediate safety gates in thin KWin shims. Use the effect staticlib for optional interaction/visual policy, not required tiling.
- Status: research, 2026-10-13. Informs the first post-0.1 [Push code down](../principles.md#layering) pass; no implementation or 0.1 schedule change. Recommendations below are proposals, not adopted architecture decisions.
- Evidence snapshot: OmniTiler `552a54ae1df46da120a1a86963949486e0f2feb8` (HEAD when inspected); all repository `file:line` locators below refer to that revision. Upstream KWin `8438567a741826da8b7536a8b10eb3af8fc8820d` (`8438567a`, tag `v6.7.4`); upstream links are pinned. Source inspection only, no runtime/performance acceptance.
- Labels: **Fact** = source-supported; **Inference** = engineering assessment/proposal; **Unknown** = not established. LOC are approximate physical lines, including comments/blanks and inline tests, excluding separate test files, generated code and build output. Mixed files are not assigned speculative movable percentages.

## 2. Verified KWin entry points and threading limits

| Fact at pinned KWin | Source evidence | Consequence (inference unless stated otherwise) |
| --- | --- | --- |
| Plain scripts instantiate `QJSEngine`; expose explicit QObject globals and console extension; evaluate a JS file. `callDBus` uses `asyncCall` and invokes a callback later. D-Bus errors warn and return without calling that callback. | [K1], [K2] | A script cannot synchronously obtain a remote Rust decision via this API. Keep timeouts and stale-reply checks; never spin a nested event loop waiting for Rust. |
| Background script loading reads bytes only. JS evaluation happens in the script-owned watcher slot. Declarative scripts instead use the shared `QQmlEngine`; KWin registers QML workspace/types. | [K1], [K3] | JS/native observation runs on the KWin-owned QObject context, not on the file-I/O worker. QML is a different integration surface, not a native-module import facility in the current plain script. |
| Startup creates input, compositor, workspace/scene and plugins from the application; Workspace creates Scripting. The application runs one Qt event loop. | [K4] | Inspected script/signal/D-Bus QObject paths are main-thread-owned; Qt owner-thread delivery is assumed under its QObject contract. KWin source does not grant Rust workers permission to touch these objects. |
| Effect loader explicitly requires effect loading on the compositor thread, where it blocks. Factories/paint hooks need current graphics context. Paint dispatch calls loaded effects directly; pointer spy/filter dispatch is synchronous before subsequent filters. | [K5], [K6] | C++-to-Rust calls inherit their caller context and latency budget. Current shim entry points include D-Bus slots, effect signals and input spy (`activewindowborder.cpp:47-142,207-305`), not an independent Rust/render pump. |
| Effect IID includes exact major.minor.patch; mismatch refuses loading. Header disclaims binary compatibility. General `PluginFactory` also embeds version and requires recompilation each release. | [K7], [K8] | Native Rust behind either shim still carries KWin ABI rebuild cost; a stable internal C ABI cannot stabilize the host plugin ABI. |
| General binary plugins are discovered in `kwin/plugins`, enabled from metadata/config, IID checked and factory-created in KWin. Installed development headers/target include Plugin, Workspace and Window. In-tree screencast uses this factory. | [K8], [K9] | A third-party non-effect plugin is technically available in 6.7.4, not a stable/sandboxed alternative. It can link native observation/actuation APIs; an OmniTiler prototype is still unverified. |
| Public KWin D-Bus provides desktop/control/query and plugin/effect/script lifecycle methods, not the complete per-window geometry/input event surface exposed to scripts/effects. | [K10], [K11] | An external Rust process still needs a KWin observation/actuation shim. This is not proof that every Wayland extension is insufficient; full Wayland coverage remains unknown. |

- **Thread constraint:** Rust may compute on worker threads using owned POD snapshots and safe channels/mutexes. Marshal results back to the original KWin owner context; recheck identity, scope, topology and cancellation before native writes. Keep synchronous input/paint decisions bounded; do not join workers, wait on remote replies, or hold worker-contended locks there. This is a proposed design constraint, not measured performance.
- **Unknown:** backend-specific render, DRM and QtQuick thread internals were not exhaustively audited. The inspected call chains establish owner-context boundaries, not that KWin has no worker threads, nor a public guarantee that every backend callback is main-thread-only.
- **Failure distinction:** refused/missing/removed plugin is different from a fault after loading. Effect/general-plugin native code shares KWin's process; Rust panic-catching cannot isolate abort, invalid-pointer UB, allocation failure or a C++ crash. Safe Rust workers improve data safety, not process isolation.

## 3. Route comparison

**Inference:** costs/suitability below follow the verified surfaces above. No new route was prototyped or benchmarked.

| Route | Sync/async and worker limits | Failure isolation / packaging / ABI | Suitable movable logic / gaming impact |
| --- | --- | --- | --- |
| A. Extend existing planner D-Bus | Async from script [K2]; Rust computation can use workers while one retained-state owner preserves ordering; native results return to script owner context. | Best process isolation; no additional KWin ABI coupling. Protocol rollout/versioning and recovery required; planner absence still suspends planning, not native KWin. | Admission, topology selection, operation policy and reconciliation. Batch normalized facts; no per-motion round trip assumed affordable. No extra native input grab; stale decisions must never resize/focus games. |
| B. Existing effect + linked Rust staticlib | Direct C ABI calls synchronous; worker-only pure computation, owner-thread snapshot/apply. Script access to effect's D-Bus remains async, even though C++ calls Rust synchronously. | No crash isolation; exact KWin ABI rebuild and existing optional-effect packaging. Must retain effect-independent tiling/fallback. | Optional visual, oracle, drag-preview policy and later accelerated interaction. Mandatory born-maximized/tiling authority here violates absence gate without independent fallback; dual authorities add complexity. Inactive/fullscreen paths must avoid overlays, input changes and repaint work. |
| C. General native `KWin::PluginFactory` + Rust | Direct native calls synchronous; input/signal owner callbacks can publish owned snapshots to workers. Not an effect and has no effect paint chain by itself [K8]. | In-process fault/startup blast radius; exact-release IID, Devel headers and new plugin packaging/lifecycle. Can be separate from missing effect, but itself may fail to load. | Could replace much TS observation/routing/state with C++ QObject shim plus Rust platform layer. Strong synchronous reach, but tiling would gain a new binary dependency unless script fallback retained. Input filtering is capability, not a reason to intercept games. |
| D. Native QML module + Rust, imported by declarative script | Potential synchronous QObject invokables and async signals, Rust workers over owned data. Requires changing current script integration to declarative QML; no demonstrated plain-JS native import [K1], [K3]. | In-process fault; new Qt/QML module packaging/import deployment. Qt-only policy module need not link KWin ABI; direct KWin access would restore that coupling. | Pure predicates/state could use a Qt-only module with workspace calls in QML shim. Feasibility/import/unload behavior unknown; added integration surface, no proved gaming/performance advantage. |
| E. WASM/other embedding inside current JS engine | No WASM runtime/bridge or native module loader provided in inspected KWin script setup [K1]. Native WASM execution feasibility unknown; JS interpreter/transpilation would be a different unverified design. | Would add runtime/toolchain/bridge or upstream host changes; JS faults differ from native embedding faults. Packaging/ABI depend on chosen implementation, currently unknown. | Not an evidence-backed migration route. Cannot assume browser `WebAssembly`/Workers in `QJSEngine`; startup/frame cost and game residual cost unmeasured. |
| F. Link safe Rust policy into KCMs behind small C ABI | Synchronous local policy; UI remains Qt owner-thread; asynchronous native I/O may be a separate later change. | KCM-host process fault, not a new compositor-loaded plugin; preserve settings-only Qt/KF build, no KWin ABI dependency (`CMakeLists.txt:8-20,163-217`). New settings Rust build/link seam needed. | Conflict/catalog/default validation first, then reconciliation reducer with explicit I/O results. High extraction value without drag-path traffic; preserve shortcut authority/consent and never introduce gameplay polling. |
| G. Generate JS policy from a shared source | Runtime remains synchronous JS; not Rust execution. No Rust worker threading. | Avoids new native dependency, adds build/schema/code-generation complexity; generation was declined for immediate born-policy lift. | Tiny mirrored predicates only, not state/native migration. Could remove hand-maintained copies but does not meet broad runtime-Rust goal; no demonstrated performance gain. |

- **WASM verdict (fact/unknown):** KWin constructs `QJSEngine`, installs console support and evaluates JS [K1]; inspected scripting/effect setup supplies no `WebAssembly`, WASM bridge, `require` or native import facility. KWin source alone does not prove every deployed Qt engine lacks an internal WASM capability. Treat Rust-to-WASM as **unverified**, not a supported route. A native WASM embedder would reduce to B/C/D plus another runtime.
- **Other external APIs:** [K10] is useful for reconfigure/query/lifecycle, not a replacement for the current `workspace` shim. No direct external-Rust full tiling route was verified. Do not mistake planner policy ownership for native actuation authority.

## 4. Extraction contracts required

**Proposals, not current wire behavior:**

| Movable area | Preferred route | Minimum contract / architecture change |
| --- | --- | --- |
| Born-maximized and other pre-dispatch decisions | A; C/D only if true synchronous access proves necessary | Add normalized admission facts (maximize/fullscreen, born vs later, tiled-first/applied/floating/sticky/fixed eligibility, current setting) and explicit clear/keep decisions. Decision must not commit a layout against pre-clear geometry. Script validates fresh lifetime/scope/eligibility, clears only authorized eligible windows, re-observes, then plans. Either a read-only preparation command plus existing planning request, or a versioned response that terminates this flight with native prerequisites and replans after readback. Avoid unconditional extra calls where no preparation is needed. |
| Output selectors / command construction | A | Supply complete normalized output topology and moving-window rectangle; Rust selects opaque target IDs. Fresh host membership/capability check still precedes dispatch/application. Current request receives locally selected domain(s); moving selection requires supplying candidates, not merely calling an already-shared predicate. |
| Adapter reconciliation / marker maps | A | Send native operation outcomes, close-vs-minimize, identity-lifetime tags, domain/config/owner generations, observed-vs-requested geometry and cancellation. Retain one policy owner; specify which local immediate invalidations survive planner loss. Current v1 commits before apply, so migrating host evidence cannot silently claim native success or invent transaction acknowledgements. |
| Workspace mapping / lifecycle | A, possibly C later | Pure logical mapping reducer with ordered host desktop/window events and observed create/remove/assign results. Synchronous native cleanup/order requirements remain in shim until async equivalent proven; no opaque QObject references cross protocol. |
| Live drag resize / sibling reflow | First evaluate A; B/C only for demonstrated latency need | Current finished-verdict pull is insufficient: need gesture ID, ordered samples, domain/topology generation, original/desired/applied geometry, cancellation and terminal fence. Separate read-only preview from committed layout; bounded latest-wins intermediate work, never drop finish/cancel/invalidation. Keep native resize on owner context, prevent feedback/reentrant signal loops and revalidate fullscreen/eligibility before every write. Worker throughput cannot make owner-thread setters parallel. |
| Effect group/visual/oracle | B | Expand POD snapshots/results, not native handles. C++ owns QObject lifetime and rendering; synchronous immediate hide/cancel gates cannot wait for workers. Optional acceleration must degrade to existing tiling on effect unload/absence. |
| KCM defaults/catalog/conflict/recovery | F | Safe Rust reducer taking typed key IDs, immutable read images, confirmed previews and write/readback results; C++ owns Qt transport, dialogs, KConfig and persistence initially. Preserve pinned KGlobalAccel owner, preimage/readback and narrow recovery; no wholesale native-store rewrite needed for first extraction. Shared catalog semantics can later align with Windows, while Qt key encoding remains KDE-specific. |

- **Compatibility:** current wire uses v1 and rejects unknown fields; TS sends `revision: 0`, with local flight/epoch and snapshot fences (`plan-adapter.ts:7904-7942,8063-8095`). Add an explicit capability/version rollout; do not rely on a revision field that currently is not a native-apply acknowledgement. Preparation timeouts, owner restart and stale replies must invalidate narrowly and resume on fresh observation.
- **Ordering/performance tradeoff:** route A can preserve clear-before-plan ordering but changes when that clear occurs relative to native signals. Whether delayed admission/extra round trips are perceptible is unknown. If same-callback timing is required, A cannot reproduce it; retain the conformance-pinned predicate or evaluate C/D rather than making the optional effect mandatory.
- **Unsafe guardrail:** [decisions.md:194-208](../decisions.md#rust-unsafe-guardrail) requires one tiny dedicated FFI module per crate, with `#![forbid(unsafe_code)]` everywhere else. Existing effect exports/raw-pointer handling occupy `drag_oracle.rs:176-262` and `group_highlight.rs:458,534-788`, plus exported ABI attributes in `visual.rs:50-169`; this is not literally one source module today. Consolidate boundary handling before expansion; new reducers/core logic remain safe. `catch_unwind` is a panic boundary, not memory/fault isolation.

## 5. Recommended staged path

1. **First post-0.1: extend A for one bounded admission slice.** Specify an explicit preparation decision/readback contract for born-maximized, keep existing eight-case policy conformance and all host eligibility lanes, then remove the KDE policy copy only after authoritative Rust decisions are proven. Consequence: async admission and protocol work; no new KWin ABI dependency and no effect requirement.
2. **Extract values before lifecycles.** Move output selection and normalized policy into core/planner; use F for KCM catalog/default/conflict predicates with a tiny FFI seam. Move platform reconciliation state one reducer at a time, retaining host observation/actuation and immediate cancellation. Consequence: incremental reduction, not instant thin shims; avoids parallel policy authorities and unnecessary new runtime/plugin machinery.
3. **Measure interaction before selecting a native replacement.** Trace callback work, planner queue/round-trip age, worker computation and native apply/readback separately. Prototype bounded drag snapshots/preview without committing on every sample; assess live sibling reflow and compare tiler-off/on frame time, input latency and fullscreen/direct-scanout behavior. Consequence: multithreading is justified by evidence, not assumed to improve native setter throughput.
4. **Use B for optional acceleration; keep C as a measured alternative.** B already links Rust and suits visual/oracle policy, but must never become the sole tiling path. If A cannot meet an established synchronous/latency requirement, spike C against the supported host floor as well as 6.7.4; compare fallback/rebuild/lifecycle costs before a user architecture choice. D/E/G are not the first pass. Consequence: stable tiling remains independent of the effect; native replacement could increase ABI/startup risk.

| Principle | Recommendation consequence / future acceptance |
| --- | --- |
| Simplicity (`principles.md:12-17`) | Reuse existing planner/FFI seams; one decision authority, bounded preparation flow; no new embedder by default. |
| Layering (`principles.md:19-27`) | Core owns portable decisions; safe platform Rust owns KWin-specific reducers; shims retain actual APIs and native evidence. Small JS safety gates may remain where simpler. |
| Resilience (`principles.md:29-45`) | Planner restart/stale reply, missing/failed/removed effect and native apply failure must converge without permanent tiling disablement or KWin instability. Preserve the release gate (`decisions.md:59-70`). |
| Gaming (`principles.md:47-57`) | No fresh input grabs, fullscreen resize/focus/overlay interference, busy waits or game-induced worker/repaint loops; measured minimal residual cost, not inferred from use of Rust. |
| Observability (`principles.md:59-65`) | Carry correlation, gesture/config/domain generations and decision/issued/observed outcomes through preparation/worker/apply; bounded normal logs distinguish stale/refused/failed/recovered without payload/user-content logging. |

## 6. Key unknowns / discriminating evidence

| Unknown | Evidence needed before implementation choice |
| --- | --- |
| Async preparation's native ordering and perceptibility | Controlled born-maximized launch/setting-change/close/fullscreen/fixed-size races; clear readback before admission, no game writes. Existing conformance table proves policy, not delayed timing. |
| Actual drag bottleneck and sustainable sibling reflow cadence | Separate source-to-callback, planning/worker age, native setter/readback and frame/input timings; bounded latest-wins cancellation/finish stress. No latency or gaming-cost benchmark was run here. |
| General plugin operational fallback and support-floor coverage | Minimal PluginFactory spike on supported 6.6 and 6.7 hosts, load refusal/unload/startup/reconfigure/rollback, effect absent, no duplicate script/native authorities. Verified availability here is 6.7.4 only. |
| QML native module availability/unload and underlying Qt WASM support | Declarative import/invokable spike with standard deployment paths; inspect the deployed Qt implementation for WASM separately. No plain-script dynamic native loader was verified. |
| Backend callback/thread details and worker teardown | Trace actual entry-thread IDs and host backend/render lifetimes; prove worker cancellation/join cannot block callback or outlive unload. Never transfer native pointers as a shortcut. |
| Protocol migration/restart-state scope | Specify capability negotiation, lifetime IDs and native-result events; separate logical commit from successful native application, including owner loss and partial writes. Full external Wayland window-management coverage is also unresearched. |
